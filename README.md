# 도쿄 산책 · 규빈 & 아내 (2026.10.17–22)

밝은 파스텔 **아이소메트릭 3D 디오라마** 여행 가이드.  
실측 지도가 아니라, 레퍼런스처럼 **애니메이션 도시 모형**으로 일정을 둘러봅니다. (1인칭 없음)

## 실행

```bash
cd "Japen tour"
python3 -m http.server 8080
```

브라우저: [http://localhost:8080](http://localhost:8080)  
(`three`·모듈 때문에 `file://` 대신 로컬 서버 필요)

## 조작

| 입력 | 동작 |
|------|------|
| 드래그 | 카메라 회전 |
| 휠 | 확대 / 축소 |
| 핀·칩·목록 클릭 | 스팟 선택 + 카메라 이동 |
| ← → | 이전 / 다음 스팟 |
| ↑ ↓ | 이전 / 다음 일차 |
| Maps 길찾기 | 해당 스팟 좌표로 외부 지도 |

## 구성

- **본체** `index.html` — 3D 디오라마 + 상세 패널 + 실측 미니맵
- `js/data.js` — 6일 일정 · 위경도 · 이동(via) + **실측 투영 `projectDay()`**
- `sample.html` — 실측 MapLibre 지도 (보조)
- `pokemon.html` — 픽셀 어드벤처 (보조)
- `reference/` — Street View / 1인칭 등 이전 실험

## 떠 있는 지도 조각

수동 모형 좌표는 없다. 스팟도 랜드마크도 전부 `lat`/`lng` 에서 나온다.

**축척이 두 개다. 숨기지 않는다.**

| | 축척 |
|--|------|
| 조각 **안** | 실제 지도 비율 그대로 (OpenStreetMap 도로·물·공원) |
| 조각 **사이** | 방위는 실측, 거리는 압축 — 압축률을 미니맵에 적는다 |

1. `tools/fetch-osm.py` 가 **700m 안의 스팟들을 한 조각으로 묶어** OSM 에서 도로망·물·공원·철도를 받아
   원형으로 잘라 `assets/osm/tile-*.json` 으로 굽는다 (조각 17장, 약 730KB)
2. `projectDay()` 가 위경도를 km 평면으로 투영한다. 기준점은 평균이 아니라 **중앙값** —
   Day 05 처럼 90km 떨어진 스팟 하나가 끼어도 나머지가 한 점으로 뭉개지지 않는다
3. 배치는 **중심에서 본 방위각을 그대로 두고 반경만** 조정한다. 조각끼리 겹치면 반경만 벌린다
4. 미니맵과 디오라마가 **같은 `projectDay()` 결과**를 쓴다. 두 그림이 어긋날 수 없다

조각 데이터가 없으면(로드 실패, 도로가 안 매핑된 산속) 잔디 원판으로 조용히 폴백한다.

### 지도 다시 굽기

```bash
python3 tools/fetch-osm.py           # 없는 조각만
python3 tools/fetch-osm.py --force   # 전부 다시
```

Overpass 는 429/504 를 자주 뱉는다. 미러를 돌아가며 재시도하고, 끝내 실패한 조각은 폴백으로 넘어간다.

## 시간대

일차마다 실제 시각이 다르므로 하늘·태양·안개·창문불을 통째로 바꾼다 (`data.js` 의 `light`).

`01` 심야 · `02` 아침 · `03` 석양 · `04` 야경 · `05` 저녁 · `06` 새벽

우상단 **시간대 바**에서 직접 고를 수도 있다. 고른 값은 일차를 바꿔도 유지되고,
`자동` 을 누르면 다시 일정 시각을 따라간다. 건물 발광은 미리 걸어 두고 세기만 바꾸므로
전환할 때 디오라마를 다시 짓지 않는다 — 즉시 바뀐다.

## 모바일

하단 시트는 3단계다. **peek**(한 줄) → **half** → **full**.
손잡이를 끌거나 탭해서 전환하고, 지도는 시트에 가려지지 않는 영역에 맞춰 자동으로 다시 프레이밍된다.
