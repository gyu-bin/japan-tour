# 프롬프트 · 포켓몬식 건물 / 건물 내부

> 대상: `legacy/pokemon2.html` 만 (골드 파일·`data.js` 일정 데이터는 건드리지 않음)
> 목표: 일정 스팟 건물을 **포켓몬 R/S~FRLG 감성**으로 구분하고, **들어가서 돌아다닐 수 있는 실내**까지 장소별로 꾸민다.
> 아래 「복사용 프롬프트」 블록을 에이전트/채팅에 통째로 붙여 쓰면 된다.

## 0. 한 줄 기획

**밖 = 한눈에 알아보는 랜드마크 스프라이트 · 안 = 그 장소가 느껴지는 디테일 룸.**  
웹에서 건진 시그니처를 **최소 2개, 권장 3~4개**로 풀고, 가구·바닥·라벨·동선까지 채워 **허전한 빈 방**이 아니게 한다.  
사진/평면도 복제는 금지. 포켓몬 센터·체육관 실내처럼 **빽빽하지만 읽히는** 밀도.

### 디테일 기준 (실내 합격선)

지금 수준의 “카운터 3개 + 테이블 몇 개”는 **미달**. 아래를 모두 만족해야 한다.

| 항목 | 최소 | 권장 |
|------|------|------|
| 맵 크기 | 22×16 | 24×18 ~ 26×18 |
| 가구/장식 오브젝트 | **12개 이상** | 16~24 (작은 화분·의자 포함) |
| 구역(존) | 2 | 3~4 (라벨로 이름 붙임) |
| 바닥 연출 | 카펫 1장 | 카펫 + 통로 + (테마) 물/다다미톤/어두운 홀 등 **2종 이상** |
| 웹 시그니처 반영 | 2 | 3~4 (색·소품·공간 구조 중) |
| 보행 동선 | 출구↔주요 존 연결 | 막힌 섬·가구에 끼임 없이 한 바퀴 가능 |
| “허전함” | 화면 절반이 빈 돌바닥이면 실패 | 벽면·가장자리도 가구/장식으로 채움 |

**실패 예:** 중앙만 가구 4개, 나머지는 회색 돌.  
**성공 예:** 하네다 = 체크인 카운터 열 + 안내 기둥감 + 코인로커 + 대기 벤치 + 게이트 표지 + 카펫 동선 + 라벨 3개.

## 1. 현재 상태 (기준점)

| 레이어 | 있는 것 | 빈칸 |
|--------|---------|------|
| 야외 `styleFor(name)` | 공항·절·맛집·마트·teamLab·숙소 등 다수 | 스팟마다 차별도·디테일 편차 큼. 기본 `shopR` 폴백 많음 |
| 야외 `renderBld` | GBA식 지붕·벽·간판 파츠 | 일부 스타일은 비슷한 박스에 간판색만 다름 |
| 실내 `interiorKind` | hotel / airport / museum / temple / restaurant / shop / tower | **매칭 안 되면 들어가기 버튼 없음** |
| 실내 `buildInteriorMap` | 종류당 1~2 룸 템플릿 | 스팟 고유 연출(가조엔·조이폴리스·황거 등) 약함 |
| 실내 가구 스프라이트 | reception, counter, bed, exhibit, crystal… | 스팟 전용 가구·NPC·짧은 대사 부족 |
| UX | 대화 → 들어가기 / 아래쪽 나가기 | 자동여행은 실내 스킵 (유지) |

## 2. 원칙 (하드 룰)

1. **파일:** `legacy/pokemon2.html` 만 수정. `pokemon.html` / `legacy/js/data.js` 일정 본문 변경 금지.
2. **톤:** 포켓몬 루비·사파이어 / 파이어레드 마을·건물. DS급 텍스처·리얼 3D·사진 텍스처 금지.
3. **브랜드:** 닌텐도/포켓몬 로고·공식 스프라이트 복제 금지. “그 게임 느낌”만.
4. **스케일:** 실내 맵 **최소 22×16**, 권장 **24×18 ~ 26×18**. 미니 던전·다층은 만들지 말 것. **허전한 작은 방도 금지.**
5. **사실성:** 실제 상호·주소·영업 정보는 `note`/Maps 링크에 맡기고, 실내는 **분위기 오마주** — 단 §0 디테일 합격선을 채울 것.
6. **자동여행:** 실내 강제 진입 없음. 수동 + 「들어가기」만.
7. **출구:** 실내 남쪽 GATE = 나가기. 야외 GATE = 마을 포탈 (기존 유지).
8. **UI 폰트:** Pretendard/시스템 고딕 유지 (갈무리 가독성 이슈).
9. **실내 밀도:** 가구 12+ · 존 라벨 2+ · 바닥 연출 2종+ · 벽/가장자리 장식. “종류만 다른 빈 템플릿” 복붙 금지.

## 3. 건물 분류 체계

모든 일정 `stops[].name` → **외관 스타일 `s`** + **실내 종류 `kind`** + **실내 테마 키 `theme`**.

```
name ──styleFor──► { s, w, h }     // 야외 스프라이트
     ──interiorKind──► kind|null   // null이면 입장 불가(또는 outdoor-only)
     ──interiorTheme──► theme      // buildInteriorMap 분기 (kind 하위)
```

### 3-1. kind (실내 장르)

| kind | 의미 | 기본 가구 키워드 |
|------|------|------------------|
| `hotel` | 숙소·료칸·로비 | reception, bed, plant, counter |
| `airport` | 공항 터미널 | counter, locker, exhibit |
| `museum` | 미술관·디지털 아트·전망 | exhibit, crystal, flower, pool |
| `temple` | 절·신사·가조엔 예식 | altar, pillar, stall, flower |
| `restaurant` | 식당·카페 | counter, table, fridge |
| `shop` | 편의점·상점가·전기거리 | shelf, fridge, stall, exhibit |
| `tower` | 전망대·로프웨이 역사 | exhibit, locker |
| `park` | 공원·해변·러닝 | **야외만** (입장 없음, 확정) |
| `arcade` | 조이폴리스 등 | stall, exhibit, locker |
| `transit` | 버스·환승 | **야외만** (입장 없음, 확정) |

`park` / `transit` / 택시 / 후지 랜드마크는 들어가기 버튼을 만들지 않는다.

## 4. 야외 건물 「포켓몬화」 체크리스트

각 `s` 스프라이트는 아래를 만족해야 한다.

1. **실루엣**만으로 구분 (호텔 vs 마트 vs 절 vs 타워).
2. **지붕 비중** 약 35~50%, 윗면/본색/처마 3단.
3. **문**이 아래 중앙 또는 약간 치우쳐 보이기 (들어갈 수 있어 보이게).
4. **간판/포인트색** 1개 (로손=파랑, 야키니쿠=갈갈, teamLab=어두운 유리+빛).
5. 캔버스 `w*16 × h*16`, 외곽 1px outline (`strokeOuterOutline`).
6. 장식용 집(`house`/`shopR`)과 **일정 랜드마크**가 헷갈리지 않게 — 랜드마크는 더 크고 색이 센 것.

### 개선 우선순위 (야외)

1. P0: `styleFor` 폴백 `shopR` 인 스팟 없애기 (전수 매핑).
2. P0: 같은 장르라도 theme별 **간판색·창문·부속물** 차이 (스시 vs 라멘 vs 몬자).
3. P1: 문 앞 1타일 길을 맵 생성 시 항상 확보 (입장 UX).
4. P2: 밤/저녁 `currentTime`에 창문 불 톤 (기존 있으면 유지·강화).

## 5. 실내 「들어가서 꾸미기」 체크리스트

### 5-1. 공통 레이아웃 (디테일 필수)

```
[나무/벽 테두리 1~2]
[  상단: 시그니처 존 A (가구 밀집)     ]
[  중단: 통로·카펫 · 존 B / 존 C       ]
[  측면: 로커·화분·의자 등 가장자리 장식 ]
[  남쪽 3칸 통로 → GATE 나가기         ]
```

- 맵: **최소 22×16** (권장 24×18).
- spawn: 출구 바로 안쪽. 출구 통로는 가구에 막히지 않게 마지막에 재확보.
- TRIG: 실내에서는 일정 트리거 null 유지.
- NPC: 해당 `stop` NPC + 가능하면 테마 점원 1명 (카운터 앞).
- 가구는 `blocked` — 플레이어가 뚫고 못 감.
- **빈 중앙 광장만 두고 가구 4~6개로 끝내지 말 것.** §0 합격선 필수.
- 부족하면 가구 스프라이트 추가: `chair`, `sofa`, `lamp`, `lantern`, `bench`, `vending`, `machine`, `neon`, `window` 등 — 기존 counter/shelf 재사용 우선, 없어도 디테일 때문에 추가 가능.

### 5-2. theme별 연출 가이드 (구현 지시용 · 밀도 포함)

각 theme는 **존 3개 + 가구 12+**를 목표로 채운다. 표의 “필수”는 시작점일 뿐, 그걸로 끝내지 말 것.

| theme | 바닥 | 필수(시작) + 채울 것 | 라벨 예 | 웹 오마주 포인트 |
|-------|------|----------------------|---------|------------------|
| haneda | 밝은 돌+중앙 카펫 복도 | counter 열, locker, exhibit, **bench·plant·안내기둥감** | 체크인 / 로커 / 게이트 | T3 넓은 홀, 카운터 열, 빨간 대기석 |
| sectionL | 크림 카펫+복도 | reception, bed, plant, **sofa·lamp·프런트 양쪽** | 프런트 / 라운지 / 객실 | 비즈니스호텔 로비+복도 |
| sensoji | 돌+중앙 카펫 | altar, pillar, stall, **lantern·flower·노점 양옆** | 본당 / 나카미세 | 붉은 문·기둥·상점가 |
| planets | 어둠+워터+통로 | pool, crystal, flower, exhibit, **locker(신발)·어두운 복도** | 워터 / 크리스탈 / 플라워 | 수심 워터룸, 무한 크리스탈, 부유감 플라워 |
| mori | 밝은 전시 | exhibit×다수, counter, **window·plant** | 전시 / 홀 | 타워 미술관 흰 홀 |
| cityview | 카펫+창측 | exhibit(창), locker, **window 벨트·bench** | 전망 덱 | 유리 난간 전망 |
| lawson | 밝은 타일 | fridge, shelf, counter, **vending·입구 매트·계산대 L자** | 냉장 / 진열 / 계산 | 편의점 표준 동선 |
| akihabara | 회색 타일 | shelf, exhibit, **neon·machine 느낌 장식** | 전기거리 | 세로 네온·빽빽한 매대 |
| monja 등 식당 | 나무톤 카펫 | counter, table×4+, **chair·fridge/sink·입구 노렌감** | 카운터 / 홀 | 상호 포인트색+좌석 밀도 |
| gajoen | 고급 카펫 | altar 변형, flower, pillar, **lamp·화단** | 화원 / 본관 | 화려한 실내 장식 |
| joypolis | 어두운 바닥 | stall, exhibit, locker, **machine×여러·티켓 카운터** | 티켓 / 게임 | 실내 테마파크 |

| aquacity / shinjuku | 몰 복도 카펫 | stall, shelf, counter, **plant·쇼윈도 exhibit** | 몰 / 숍 | 상업 복도 |

### 5-3. UX 카피

- 대화 버튼: `🚪 들어가기`
- 게이트 라벨: 실내 `나가기` / 야외 `출구`
- HUD 타이틀: `{짧은이름} · {숙소|공항|…}`
- 들어가면 짧은 토스트 가능(선택): `○○ 안으로 들어왔다!`
- 존 라벨은 **한글 짧게** (워터 / 프런트 / 체크인).

## 6. 작업 단계 (구현 시 순서)

1. **매핑표 코드화** — `styleFor` / `interiorKind` / `interiorTheme(name)` 를 표와 일치.
2. **야외 P0** — 빠진 `s`·약한 스프라이트부터 `renderBld` 보강.
3. **실내 전 스팟 입장** — 제외 목록만 null.
4. **theme 분기 + §0 디테일 합격선** — 가구 12+, 존·바닥·가장자리까지. 빈 템플릿 금지.
5. **가구 스프라이트** — 부족분 추가 (chair/sofa/bench/lamp/vending 등).
6. **스모크** — 입장 후 “허전한가?”를 기준으로 보고, 허전하면 가구 추가 후 재검.

## 7. 복사용 프롬프트

### 7-A. 마스터 (전체 패스)

```
역할: 도쿄 여행 포켓몬풍 맵 게임의 건물/실내 아트·로직 담당.

대상 파일: legacy/pokemon2.html 만 수정.
금지: legacy/pokemon.html 본문, legacy/js/data.js 일정 데이터, 닌텐도/포켓몬 공식 자산.

목표:
1) 모든 일정 스팟의 야외 건물을 포켓몬 R/S~FRLG 감성으로 구분되게 그린다.
2) 입장 가능한 스팟은 「들어가기」로 실내에 들어가고, **§0 디테일 합격선**을 만족하는 방으로 꾸민다.
3) docs/프롬프트-포켓몬-건물.md 매핑표·원칙·디테일 기준을 따른다.

하드 룰:
- 팔레트·파츠는 기존 PAL / roofBand / wallFace / door / sign / awning 재사용.
- 실내 맵 최소 22×16 (권장 24×18), 가구 12+, 존 라벨 2+, 바닥 연출 2종+. 허전한 빈 방 금지.
- 남쪽 GATE=나가기, 자동여행은 실내 강제 진입 없음.
- 사진 텍스처·실사 UI 금지. 도트 타일만. 패치만.

작업 순서:
A. styleFor + interiorKind + interiorTheme 를 매핑표와 일치 (입장 제외: 택시/후지/버스/공원·해변·황거).
B. renderBld 야외 랜드마크 보강.
C. buildInteriorMap을 theme별로 **밀집 배치**. 가구 스프라이트 부족분(chair/sofa/bench/lamp/vending/machine/neon/window 등) renderBld에 추가.
D. UX(들어가기/나가기/HUD) 유지.
E. 스모크: 호텔·공항·teamLab·식당·로손 — 들어가서 한 바퀴 돌 때 허전하지 않은지 확인.

성공 기준:
- 폴백 shopR 일정 랜드마크 없음.
- 입장 허용 스팟에 들어가기 있음.
- 실내마다 §0 표(가구12+/존2+/바닥2종+) 충족. 카운터만 몇 개 있는 방은 실패.
- 나가면 해당 스팟 앞 야외 스폰.
```

### 7-B. 야외 건물만 (스프라이트 패스)

```
legacy/pokemon2.html 의 renderBld + styleFor 만 개선한다.

목적: 일정 스팟 건물을 포켓몬 GBA 마을 건물처럼 「실루엣만으로」 구분.
참고 톤: 루비/사파이어 포켓몬센터·프렌들리숍·체육관 지붕 비율(지붕 35~50%, 3단 색, 오른쪽 두께감).

요구:
- styleFor(name) 매핑을 docs/프롬프트-포켓몬-건물.md §3-2 표에 맞출 것.
- 각 s마다 문·간판·포인트색 1개 이상. 비슷한 박스+색만 바꾸기 금지(맛집은 차양/철판/초밥카운터 등 소품으로 구분).
- w/h는 타일 단위, 캔버스는 w*16×h*16, strokeOuterOutline 유지.
- 장식용 house/shopR 와 랜드마크가 같은 크기로 보이지 않게 랜드마크를 더 크게.

하지 말 것: 실내 로직 대규모 변경, data.js 수정, 새 이미지 파일 로드.
```

### 7-C. 실내만 (디테일 꾸미기 패스)

```
legacy/pokemon2.html 의 실내를 「허전하지 않게」 다시 꾸민다.
기준 문서: docs/프롬프트-포켓몬-건물.md §0 디테일 합격선 + §5.

이미 있는 것: interior 상태, enterInterior/exitInterior, 얇은 buildInteriorMap 템플릿.
문제: 종류당 가구 몇 개만 있어 빈 방처럼 보인다. 그걸 고치는 게 이번 패스의 전부다.

할 일:
1) 맵을 최소 22×16 (권장 24×18)으로 키운다.
2) interiorTheme(name) 분기. 스팟마다 존 3~4, 라벨, 바닥 2종 이상.
3) 가구/장식 12개 이상. 가장자리·벽면도 채운다 (plant, chair, bench, lamp, locker…).
4) 웹에서 시그니처 3~4를 메모하고 배치에 반영 (사진 트레이스 금지).
5) 부족한 가구 s만 renderBld에 추가. 동선·출구 통로 확보.
6) 자동여행은 실내 진입 안 함. UX 버튼/나가기 유지.

합격/불합격:
- 불합격: 카운터·테이블만 있고 화면 절반이 빈 돌바닥.
- 합격: 한 바퀴 돌며 존 이름이 읽히고, 장소가 “무엇인지” 가구만으로 짐작됨.

검증: Section L, 하네다, teamLab, 로손, 몬자, 센소지 — 각각 입장 후 허전함 없는지 확인.
```

### 7-D. 스팟 단위 (한 장소 · 디테일 강제)

`{스팟이름}` / `{theme}` / `{시그니처 3~4}` 만 바꿔서 반복.

```
legacy/pokemon2.html 에서 「{스팟이름}」 실내만 디테일하게 만든다.

필수:
- theme={theme}
- 맵 ≥22×16, 가구 ≥12, 존 라벨 ≥2, 바닥 연출 ≥2
- 웹 오마주 시그니처: {시그니처 3~4개}
- 가장자리 장식 + 출구 통로 재확보
- 야외 styleFor/renderBld도 시그니처 1개는 반영
- 다른 스팟·data.js·pokemon.html 변경 금지
- 끝나면 입장→한 바퀴→나가기 스모크. 허전하면 가구 더 넣고 재제출.
```

### 9-1. 인터넷 참고 — 괜찮음 / 안 됨

**괜찮음 (권장)**
- 공식·지도·후기에서 “이 장소 하면 이거” **3~4개** 고르기  
  예: teamLab → 워터룸 + 크리스탈 + 플라워 + 로커 / 하네다 → 카운터 열 + 로커 + 벤치 + 게이트 표지
- 색·실루엣·가구 밀도·존 나누기로 옮기기
- 상호명은 일정에 있는 표기만

**안 됨**
- 사진·평면도·로고 트레이스, 실사 텍스처 붙이기, 정확한 방 복원

**한 줄:** 참고는 무드보드, 결과물은 **디테일 있는** 포켓몬 실내 (빈 방은 실패).

### 9-2. 추천 작업 루틴 (스팟 하나)

1. 웹에서 시그니처 **3~4개** 메모
2. 야외에 1개 반영
3. 실내에 나머지 + §0 합격선까지 가구 채우기 (허전하면 더 넣기)
4. 들어가기→한 바퀴→나가기 스모크
5. 다음 스팟

승인 반영: `park 야외만, 천천히 전수, 웹 참고 오마주, 실내는 디테일 합격선 필수`
